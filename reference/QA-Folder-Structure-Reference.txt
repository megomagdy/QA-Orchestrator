1. GLOBAL FOLDER (Master Copy — One on your machine)
════════════════════════════════════════════════════

Location: Wherever you choose — the path is stored in the QA_GLOBAL_HOME
          environment variable, set once by /init-workspace
          (e.g., C:\Users\you\QA-Global or ~/qa-global)
Purpose: Source of truth. /init-workspace configures it once per user.
         /init-project copies FROM here.
         /sync-global pushes BACK to here.

QA-Global/
│
├── README.md                                 ← Start here: quick start,
│                                               sharing rules, design notes
│
├── workspace.config.json                     ← YOUR tools (tracker, test
│                                               tool, docs platform) —
│                                               created by /init-workspace
│                                               (not shipped; per user)
│
├── templates/
│   ├── QA_Test_Design_Playbook_-_Template.md ← Master playbook template
│   │                                            with {PLACEHOLDER} values
│   │                                            Updated by /sync-global
│   ├── qa-rules-condensed.md                 ← All skills condensed to
│   │                                            essential rules only
│   │                                            Updated by /sync-global
│   ├── CLAUDE-md-skills-section.md           ← Skills → workflow mapping
│   │                                            Appended to CLAUDE.md
│   │                                            during /init-project
│   ├── CLAUDE-md-caching-section.md          ← Token optimization rules
│   │                                            Appended to CLAUDE.md
│   │                                            during /init-project
│   └── qmetry-template.xlsx                  ← EXAMPLE test-tool import
│                                                template (Qmetry format,
│                                                sanitized sample data).
│                                                Register YOUR tool's real
│                                                template via /init-workspace

│   │                                            to .env — never share .env)

│                                                copy to <tracker>.js and

│
├── reference/                                ← Human-readable documentation
│   ├── QA-Commands-Reference.txt               (this file and its siblings)
│   ├── QA-Agents-Reference.txt
│   └── QA-Folder-Structure-Reference.txt

├── agents/                                   ← 10 subagent files

2. PROJECT FOLDER (Created by /init-project for each project)
═════════════════════════════════════════════════════════════

Location: e.g., C:\Users\you\Projects\MyModule
Purpose: Working copy. All commands read/write HERE.
         /sync-global pushes learnings back to global.

4. THE LIFECYCLE
════════════════

First time ever (per user/machine):
  → Copy the Global Folder anywhere on your machine
  → Open Claude Code IN the global folder and ask it to run
    skills/init-workspace/SKILL.md (the /init-workspace slash
    command isn't registered until the wizard installs the skills
    user-level into ~/.claude/skills/ — after that, every /command
    works in any folder)
  → The wizard sets QA_GLOBAL_HOME, captures YOUR tracker/test
    tool/docs platform in workspace.config.json, optionally sets
    up a bug-reporter adapter + credentials

New project:
  → /init-project [name]  (available anywhere after /init-workspace)
  → Resolves the Global Folder from QA_GLOBAL_HOME (or asks)
  → Copies everything into project
  → Fills in CLAUDE.md placeholders

During project work:
  → All commands read/write PROJECT files only
  → Manual testing: type bugs into Manual Execution/Bug Summaries.txt,
    drop evidence into Epic N/ subfolders (Bug {m}.png / .mp4),
    then /report-bugs creates + attaches everything in batch
  → /learn updates project's CLAUDE.md + qa-rules-condensed.md
  → /checkpoint saves session context in project folder
  → /session-resume loads from project folder

End of project or sprint:
  → /sync-global
  → Generalizes learnings (removes project-specific names)
  → Pushes back to Global Folder
  → Global Folder now has latest knowledge

Next project:
  → /init-project [new-name]
  → Copies from Global Folder (now includes all previous learnings)
  → New project starts with accumulated knowledge from ALL past projects
